## 1. 背景与问题

第一期解决了「收得进、读得了、能搜到」。用户真实痛点下沉为：

1. **囤积后不愿整理**：手动打标签、移收藏夹成本高，库越大越乱。
2. **长文难消化**：尤其音视频转写稿、长公众号，缺少结构化速览。
3. **期望「智能」但怕失控**：全自动归档一旦错了，比没分类更糟。

**一句话**：用 AI **建议**整理方向、按需生成思维导图；**默认不无人值守改库**。

## 2. 产品目标

### 2.1 第二期目标（Must / Should）

| 优先级 | 目标 | 说明 |
| --- | --- | --- |
| Must | AI 建议标签 | 解析成功后异步生成标签建议；用户确认后才写入 `item_tags` |
| Must | AI 建议收藏夹 | 基于用户已有夹列表给出建议；用户确认后才改 `folder_id` |
| Must | 按需思维导图 | 阅读页主动触发；生成结构化树并缓存；可强制重生 |
| Should | AI 总开关与隐私说明 | 设置可关闭；隐私政策写明正文可能送模型处理 |
| Should | 待确认入口 | 「AI 待整理」列表，批量采纳/忽略建议 |
| Could | 高置信度自动采纳标签 | 仅标签、仅已存在标签名、可随时关；**默认关** |
| 不做（本期） | 通用 Agent / 对话整理 | 见 §2.2；预留第三期 |

### 2.2 非目标（第二期明确不做）

- **通用 Agent**：多步自主规划、对话式「帮我整理本周收藏」、自行调用任意工具写库。
- **默认全自动进收藏夹**：夹为单选，误归档成本高；本期仅「建议 → 确认」。
- **入库时全量生成思维导图**：成本高、非人人需要；仅按需。
- **替代解析 / 标注**：解析仍是规则抽取；标注仍是用户划线；AI 不生成标注。
- **智能列表（规则引擎列表）**：与一期一致，不另开「智能列表」产品线。
- **对外主打「第二大脑 / AI 知识库」**：能力与话术对齐「辅助整理 + 结构化速览」。

### 2.3 与第一期原则的关系

| 一期约定 | 二期怎么落地 |
| --- | --- |
| 不做无人值守智能分类 | AI 产出写在建议区（`ai_meta`），确认后才改夹/标签 |
| 解析 / 标注非 AI | 不变；AI 是第三条能力线 |
| 少发版（解析链路偏后端） | AI 同样后端队列 + API；App 消费建议与导图 |

### 2.4 第三期预留（不在本期开发）

- **整理助手（轻量 Agent）**：自然语言批量整理；工具限于查夹/标签、提建议；写库仍经确认或显式授权。
- AI 摘要 / 关键点（与导图部分重叠，避免三件并行首发）。
- 对话问答、跨条目推理。

## 3. 用户与场景

### 3.1 目标用户（在一期基础上）

- 已有一定收藏量、开始「懒得分类」的用户。
- 常存长文 / 播客 / 视频、需要快速抓住结构的人。
- 愿意开 AI、但要求「我能改、能关」的人。

### 3.2 核心场景

| 场景 | 用户行为 | 期望结果 |
| --- | --- | --- |
| 解析完成后有建议 | 打开条目或「AI 待整理」 | 看到 3～5 个建议标签 + 1 个建议夹；可一键采纳 |
| 不想用 AI | 设置关闭 AI | 不再请求模型；已有建议可忽略；主路径收藏不受影响 |
| 读长文想看结构 | 阅读页点「思维导图」 | 加载后展示可折叠树；再次进入可复用缓存 |
| 批量清积压 | 打开待整理列表 | 多选采纳标签 / 移入建议夹 / 全部忽略 |
| 文稿已转写 | 音视频条目有 transcript | 建议与导图可优先用文稿文本（无正文时兜底） |

### 3.3 成功时刻（Must-win）

1. 第一次建议标签被用户采纳且「看起来合理」。
2. 第一次思维导图在 30 秒内出树，且用户觉得「比从头读快」。
3. 用户发现关 AI 后收藏/阅读一切正常（无绑架感）。

## 4. 方案总览

```
解析 success ──► aiSuggestQueue（可选，受用户开关控制）
                      │
                      ▼
              LLM 结构化输出（标签 + 收藏夹建议）
                      │
                      ▼
              items.ai_meta（建议态，不改 item_tags / folder_id）
                      │
         ┌────────────┴────────────┐
         ▼                         ▼
   用户确认采纳              忽略 / 过期
         │
         ▼
   PUT tags / PATCH folderId（现有 API）

阅读页「生成思维导图」──► aiMindmapJob ──► ai_meta.mindmap（缓存）
```

**形态**：固定 Workflow + Tool（单次/少数次 LLM 调用 + JSON Schema），**不是 Agent**。

**工程对齐**：复用转写链路经验——进程内/队列异步、状态写 JSON、App 轮询或进详情拉取、失败不阻断主路径。

## 5. 功能需求

### 5.1 AI 建议标签（Must）

#### 行为

- 触发时机：条目 `status == success` 且用户开启 AI；异步入队，不阻塞解析返回。
- 输入：`title` + `summary` 或 `content` 截断（去 HTML、限 token）；可选 `platform`；若有文稿转写成功文本可并入。
- 输出：3～5 个短标签名（优先匹配用户已有标签名；可建议新建名）+ 可选 score。
- 落库：仅写入 `ai_meta.tags`；**不**自动插入 `item_tags`（除非用户打开「高置信度自动采纳」且满足 §5.5）。
- App：阅读页 / 详情展示建议 chips；「采纳所选」「全部忽略」。采纳调用现有 `PUT /api/items/:id/tags`（合并已有标签，不去掉用户已选手动标签，除非产品另定「替换模式」——默认 **合并**）。

#### 边界

- 无标题且无正文/文稿：跳过或标记 `ai_meta.status = skipped`，不报错打扰用户。
- 模型失败：`failed` + 可重试；不影响收藏。

### 5.2 AI 建议收藏夹（Must）

#### 行为

- 与标签建议同一次（或紧随的）LLM 调用中产出，减少成本。
- 输入另附：**当前用户自建收藏夹 id + name 列表**（含「未分类」语义）。
- 输出约束：
  - 优先 `suggestedFolderId`（必须属于该用户夹）；或
  - `suggestedNewFolderName`（仅建议新建，不自动建夹）；或
  - 保持未分类（明确输出）。
- 落库：`ai_meta.folder`；确认后 `PATCH /api/items/:id` 的 `folderId`。
- **禁止**默认静默改 `folder_id`。

#### 边界

- 用户只有「未分类」：可只建议新建夹名，或跳过夹建议只出标签。

### 5.3 按需思维导图（Must）

#### 行为

- 入口：阅读页「思维导图」（有正文或有文稿时可点；否则灰显并说明）。
- 触发：`POST …/mindmap`（或统一 AI 任务接口）；状态 `pending → success | failed`。
- 输出：树形 JSON，例如 `{ "title": "…", "children": [ … ] }`；深度建议 ≤ 3～4，节点文案短。
- 缓存：同一 `itemId` + 内容指纹（正文/文稿 hash）未变则直接返回；提供「重新生成」。
- 展示：一期可用可折叠大纲树；不要求炫酷力导向脑图 UI。
- 长文：可先摘要再导图（实现细节），对用户只体现为一次生成。

#### 边界

- 生成中再次点击：返回当前任务状态，不重复扣费。
- 失败：明确文案 + 重试；不污染阅读正文区。

### 5.4 AI 开关与隐私（Should）

- 设置：「AI 辅助整理」总开关（默认：**开** 或 **关** —— 上线前定一版；若审核/隐私敏感，建议默认关或首次弹窗征求同意）。
- 关闭后：不再入队建议任务；不发起导图请求（或导图也受同一开关约束——建议导图单独开关或共用总开关，产品二选一并写进设置文案）。
- 隐私政策 / 支持页：说明为提供建议与导图，可能将标题与正文片段发送至云端大模型；可关闭。

### 5.5 待整理与自动采纳（Should / Could）

| 能力 | 优先级 | 规则 |
| --- | --- | --- |
| 「AI 待整理」列表 | Should | `ai_meta` 有未处理建议的条目；支持批量采纳标签、逐条确认夹、忽略 |
| 高置信度自动贴标签 | Could | 默认关；仅当 score ≥ 阈值且标签名已存在于用户标签库；写入后可在条目上撤销；**不对收藏夹自动生效** |

### 5.6 非功能需求

| 项 | 要求 |
| --- | --- |
| 隔离 | AI 失败不得导致解析失败或条目不可读 |
| 成本 | 用户级或全局配额（日调用次数 / token）；超限友好提示 |
| 可观测 | 日志含 itemId、阶段耗时、模型名、成功/失败；建议采纳率埋点（服务端或后续分析） |
| 安全 | Prompt 注入防护（用户正文当数据不当指令）；输出 JSON Schema 校验；夹 id 必须二次校验归属 |
| 多端 | 建议与导图以服务端为准；扩展端可后置只读展示 |

## 6. 数据与 API（约定）

### 6.1 存储

在 `items` 上增加 JSON 字段（名称可最终定为 `ai_meta`）：

```json
{
  "status": "none | pending | success | failed | skipped",
  "tags": [{ "name": "职场", "score": 0.82, "existingTagId": 12 }],
  "folder": {
    "folderId": 5,
    "name": "运营学习",
    "suggestNewName": null
  },
  "mindmap": {
    "status": "none | pending | success | failed",
    "tree": { "title": "…", "children": [] },
    "contentHash": "…",
    "generatedAt": "ISO-8601"
  },
  "model": "…",
  "error": null,
  "generatedAt": "ISO-8601",
  "reviewedAt": null
}
```

- 建议被采纳或忽略后：可设 `reviewedAt`，或清除 tags/folder 建议区，避免列表长期噪音。
- 迁移：新增 SQL 增量脚本（如 `008_item_ai_meta.sql`），执行方式对齐现有 `pnpm db:migrate`。

### 6.2 API（草案）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/items/:id` | `item` 中带 `aiMeta`（map 后） |
| GET | `/api/items/:id/ai-status` | 轻量轮询建议/导图状态（可选，类似 transcript-status） |
| POST | `/api/items/:id/ai-suggest` | 手动触发/重跑建议（force） |
| POST | `/api/items/:id/ai-suggest/apply` | body：选中的 tagIds/names、folderId；服务端写库并标记已审 |
| POST | `/api/items/:id/mindmap` | 触发或返回缓存导图 |
| GET | `/api/ai/pending` | 待整理列表（可选） |
| PATCH | `/api/me/settings` | AI 开关等（若尚无用户设置表则本期补） |

标签/夹的最终写入优先复用现有：

- `PUT /api/items/:id/tags`
- `PATCH /api/items/:id` `{ folderId }`

### 6.3 队列

- `aiSuggestQueue`：解析成功后入队；串行或有限并发（防打爆模型与账单）。
- `aiMindmap`：可与建议共用 worker，按任务类型分支；导图优先级可低于建议。

## 7. App 交互要点

| 界面 | 要求 |
| --- | --- |
| 阅读页 | 建议标签区（可折叠）；建议夹一行 +「移入」；「思维导图」入口与 loading/失败态 |
| 设置 | AI 开关；可选「自动采纳高置信度标签」；链到隐私说明 |
| 待整理 | 列表卡片展示建议摘要；批量操作 |
| 空态 | 无建议 / AI 关闭 / 内容不足 的文案区分清楚 |

视觉：遵循现有阅读页纸白与内容栏对齐；AI 区块可用轻量区分（避免喧宾夺主），不做成仪表盘。

## 8. 模型与供应商（实现选型，产品约束）

- 优先国内可用、结构化输出稳定的 LLM（与现有阿里云体系可同云，便于运维，但不绑定产品文案）。
- 必须：**JSON Schema / 严格 JSON** + 服务端校验；夹 id 再查库。
- 密钥仅服务端；客户端不持有模型 Key。

## 9. 里程碑

| 里程碑 | 周期（参考） | 交付 |
| --- | --- | --- |
| M1 | ~2 周 | `ai_meta` + 建议队列 + 仅标签建议 + 阅读页采纳/忽略 + AI 开关 |
| M2 | ~2 周 | 收藏夹建议 + 待整理列表；可选高置信度自动标签（默认关） |
| M3 | ~3–4 周 | 按需思维导图 API + 阅读页大纲树 + 缓存与重生 |
| M4 | ~1–2 周 | 配额、成本看板/日志、失败降级打磨、隐私文案上线 |

总长约 **6～10 周**，可按人力裁剪（可先 M1+M3 若更看重导图卖点）。

## 10. 验收标准

1. 关闭 AI：新条目不再产生建议；收藏/解析/转写不受影响。
2. 开启 AI：解析成功后一段时间（如数分钟内）出现标签建议；未确认前 `item_tags` 不变。
3. 采纳标签后，标签列表与筛选结果正确；手动已有标签默认保留（合并策略）。
4. 确认移夹后，仅该条 `folder_id` 变化，且夹必须属于当前用户。
5. 思维导图：首次生成有 pending；成功后离线再进可读缓存；改正文/文稿后 force 可重生。
6. 模型故障：条目仍可打开；UI 有失败与重试，无崩溃。
7. 不出现「Agent 式」多步自主改多条数据的行为。

## 11. 开放问题

1. AI 总开关默认开还是关？是否首次使用弹窗同意？
2. 思维导图是否与「建议整理」共用一个开关？
3. 采纳标签默认「合并」还是「替换为 AI 所选」？
4. 待整理是否进首页板块，还是仅设置/我的收藏入口？
5. 配额：免费用户日限额多少？是否与后续会员绑定？
6. 扩展（Chrome）二期是否展示建议只读，还是仅 App？
7. 导图导出（图片/Markdown）是否纳入 M3，还是后置？
