## 1. 背景与问题

第一期解决了「收得进、读得了、能搜到」。用户真实痛点下沉为：

1. **囤积后不愿整理**：手动打标签成本高，库越大越乱。
2. **长文难消化**：尤其音视频转写稿、长公众号，缺少结构化速览。
3. **期望「智能」但怕失控**：后台自动打标一旦错了，比没分类更糟。

**一句话**：AI **只在阅读页、用户点一下才跑**——建议标签或生成思维导图；**确认后才改标签**；**不做任何后台自动 AI**。**分类以标签为主**；收藏夹不在二期 AI 范围（见 §2.4）。

## 2. 产品目标

### 2.1 核心原则：全手动

| 原则 | 说明 |
| --- | --- |
| **不自动** | 解析成功、入库、回前台等 **均不** 触发 AI |
| **入口统一** | 标签建议、思维导图 **仅** 从阅读页（或阅读页「更多」）主动触发 |
| **建议不直写** | 标签建议展示后须用户采纳；**永不** 静默写入 `item_tags` |
| **与转写一致** | 交互参照「转写文稿」：用户意图明确 → 异步任务 → 本页看结果 |

### 2.2 第二期目标（Must / Should）

| 优先级 | 目标 | 说明 |
| --- | --- | --- |
| Must | 阅读页 · AI 建议标签 | 用户点击后生成建议；确认后才 `PUT tags` |
| Must | 阅读页 · 思维导图 | 用户点击后生成；结构化树缓存；可重生 |
| Should | 首次使用说明 | 用户 **第一次** 点任一 AI 入口时弹一次性说明；确认后继续；按账号记已读 |
| Should | 隐私说明 | 隐私政策 / 支持页说明：仅在用户主动点击 AI 功能时可能送正文至模型 |
| 不做（本期） | 设置里的 AI 功能开关 | 不用总开关；不想用则不点入口即可 |
| 不做（本期） | 解析后自动建议标签 | 入库链路零 AI |
| 不做（本期） | 自动贴标签 / 高置信度采纳 | 任何写入须用户在阅读页确认 |
| 不做（本期） | 「AI 待整理」全局列表 | 无后台积压；每条在阅读页当场处理即可 |
| 不做（本期） | AI 建议收藏夹 / 自动进夹 | 分类以标签为准 |
| 不做（本期） | 通用 Agent / 对话整理 | 预留第三期 |

### 2.3 非目标（第二期明确不做）

- **任何无人值守 AI**（含解析后入队、定时批量、自动导图）。
- **设置内 AI 总开关**（无开关；入口常显，用户不点即不用）。
- **思维导图导出**（Markdown / 图片等）：格式后续再定。
- **替代解析 / 标注**；**智能列表**；**第二大脑话术**。

### 2.4 收藏夹与标签（产品方向）

- **二期 AI 只服务标签**（手动触发）。
- **收藏夹（一期已有）**：不做 AI；手动移夹保留；后续可能弱化/下线——单独立项。

### 2.5 第三期预留

- 整理助手（轻量 Agent）、摘要、对话问答等；仍须明确用户授权边界。

## 3. 用户与场景

### 3.1 核心场景

| 场景 | 用户行为 | 期望结果 |
| --- | --- | --- |
| 想打标签懒得想 | 阅读页点「AI 建议标签」 | loading → chips → 勾选采纳 |
| 读长文想看结构 | 阅读页点「思维导图」 | loading → 脑图（中心节点 + 分支连线）；再进可读缓存 |
| 不想用 AI | 不点阅读页 AI 入口 | 无任何模型请求；收藏/解析/转写正常 |
| 音视频无正文 | 已有文稿转写 | 两个 AI 入口可用转写文本作输入 |
| 误触 / 不满意 | 点忽略或重新生成 | 不改标签 / 覆盖旧导图缓存 |

### 3.2 成功时刻（Must-win）

1. 用户 **主动点** 后，标签建议合理且采纳流畅。
2. 思维导图 **主动点** 后 30 秒内可用，比通读更快抓住结构。
3. 用户清楚：**不点就不会送内容给 AI**。

## 4. 方案总览

```
（无解析后自动分支）

阅读页 用户点「AI 建议标签」
         │
         ▼
    POST …/ai-suggest ──► aiJobQueue ──► LLM ──► ai_meta.tags
         │                                      │
         ▼                                      ▼
    本页 loading / 轮询              展示 chips → 用户采纳
         │                                      │
         └──────────────────────────────────────► PUT …/tags

阅读页 用户点「思维导图」
         │
         ▼
    POST …/mindmap ──► aiJobQueue ──► LLM ──► ai_meta.mindmap（缓存）
         │
         ▼
    本页脑图 / 失败重试
```

**形态**：固定 Workflow + Tool；**不是 Agent**。

**工程对齐**：与转写类似——用户触发 → 异步 job → JSON 状态 → 阅读页轮询/刷新；失败不阻断阅读。

## 5. 功能需求

### 5.1 阅读页 · AI 建议标签（Must）

#### 入口

- 阅读页 **更多** sheet 和/或正文区下方操作区：**「AI 建议标签」**（与「转写文稿」并列层级）。
- 内容不足（无标题且无正文/文稿）时 **灰显** + 说明。

#### 行为

- **仅** 用户点击后 `POST …/ai-suggest`；异步入队，本页 loading。
- 输入：`title` + `summary`/`content` 截断；可选 `platform`；可并入成功转写文稿。
- 输出：3～5 个标签名（优先匹配用户已有标签；可建议新建名）。
- 落库：`ai_meta.tags`；**不** 写 `item_tags`。
- 展示：建议 chips +「采纳所选」「忽略」；采纳 `PUT …/tags`（默认 **合并** 已有手动标签）。
- 再次点击：可 force 重跑（覆盖未采纳的旧建议）。

#### 边界

- 模型失败：本页错误 + 重试；条目可读。
- 未点按钮：**永不** 产生建议、不消耗配额。

### 5.2 阅读页 · 思维导图（Must）

#### 入口

- 阅读页：**「思维导图」**（与标签建议同级入口）。
- 有正文或文稿时可点；否则灰显。

#### 行为

- **仅** 用户点击后 `POST …/mindmap`；`pending → success | failed`。
- 输出：JSON 树 `{ title, children[] }`；深度 ≤ 3～4。
- 缓存：内容 hash 未变则直接返回；提供「重新生成」。
- 展示：**脑图形式**（见下）；**不做** 导出（后续再定）。

#### 展示形态（脑图，非大纲列表）

- **视觉**：中心主题节点 + 分支节点 + 连线（类 XMind / MindNode），**不是** 缩进文字大纲树。
- **布局**：阅读页正文下方卡片内嵌画布；主节点居中或略偏中，一二级分支向左右展开；窄屏可横向滑动或双指缩放查看全貌。
- **交互**：点击节点可折叠/展开其子分支；提供「重新生成」；失败可重试。
- **样式**：与 AI 建议标签结果区一致——轻量 `#F3F6FA` 卡片底，画布内白底；中心节点品牌色，分支节点浅底 + 连线。
- **数据**：仍存 JSON 树；App 负责将树布局为脑图，不要求 LLM 输出坐标。

#### 边界

- 生成中防重复提交；失败可重试。

### 5.3 隐私与首次说明（Should）

- 隐私政策 / 支持页：说明 **仅在用户主动点击**「AI 建议标签」或「思维导图」时，可能将标题与正文片段发送至云端大模型。
- **不设** 设置项里的 AI 开关；控制方式 = 用户是否点击入口。
- **首次点击说明（已定）**：用户 **第一次** 在阅读页点「AI 建议标签」或「思维导图」任一入口时，先弹 **一次性说明**（非开关、非拦截永久使用）：
  - 要点：将使用标题/正文（或文稿）生成建议或导图；内容会发送至云端大模型处理。
  - 操作：**「知道了，继续」** 关闭并执行本次请求；**「取消」** 关闭弹窗、**不** 发起 AI 请求。
  - 已读标记：按 **用户账号** 本地或服务端记 `aiIntroSeen`（两入口共用，只弹一次）。
  - 不在设置里提供「再看说明」入口（MVP 可省略；需要时后续加）。

### 5.4 非功能需求

| 项 | 要求 |
| --- | --- |
| 隔离 | AI 失败不影响解析/阅读/转写 |
| 成本 | 按 **用户主动触发次数** 计配额；超限提示 |
| 可观测 | itemId、任务类型、耗时、成功/失败 |
| 安全 | JSON Schema 校验；tag 归属校验 |
| 多端 | 二期以 App 阅读页为主；扩展后置 |

## 6. 数据与 API（约定）

### 6.1 存储

`items.ai_meta` JSON（示例）：

```json
{
  "tags": {
    "status": "none | pending | success | failed | skipped",
    "items": [{ "name": "职场", "existingTagId": 12 }],
    "error": null,
    "generatedAt": "ISO-8601"
  },
  "mindmap": {
    "status": "none | pending | success | failed",
    "tree": { "title": "…", "children": [] },
    "contentHash": "…",
    "generatedAt": "ISO-8601"
  },
  "model": "…"
}
```

- 标签建议被采纳或忽略：可清空 `tags.items` 或记时间戳，避免阅读页长期挂旧建议。

### 6.2 API（草案）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/items/:id` | 含 `aiMeta` |
| GET | `/api/items/:id/ai-status` | 轮询 tags/mindmap 的 pending 状态（可选） |
| POST | `/api/items/:id/ai-suggest` | **用户手动**触发标签建议；body 可选 `{ force }` |
| POST | `/api/items/:id/ai-suggest/apply` | 采纳所选 tagIds/names |
| POST | `/api/items/:id/mindmap` | **用户手动**触发；body 可选 `{ force }` |

**不做**：`GET /api/ai/pending`（无全局待整理列表）；**不做** `aiEnabled` 等用户级 AI 开关字段（除非后续会员配额等另需）。

标签写入复用：`PUT /api/items/:id/tags`。

### 6.3 队列

- `aiJobQueue`：**仅** 响应 `POST ai-suggest` / `POST mindmap`；**不** 订阅解析成功事件。
- 可与转写共用 worker 进程，任务类型隔离。

## 7. App 交互要点

| 界面 | 要求 |
| --- | --- |
| 阅读页 · 更多 | 「AI 建议标签」「思维导图」（与转写文稿同级；**常显**，内容不足时灰显） |
| 阅读页 · 首次说明 | 第一次点任一 AI 入口 → 说明弹窗 → 继续才发请求 |
| 阅读页 · 结果区 | 标签 chips + 采纳/忽略；导图脑图 + loading/失败/重生 |
| 阅读页 · 底栏 | 星标 · 标签 · 备注 · 更多（标注不在底栏，选中正文添加） |
| 无 | 设置 **无** AI 开关；首页 **无** AI 待整理角标；解析完成 **无** AI toast |

视觉：AI 结果区轻量区分；对齐现有阅读页纸白与内容栏宽度。

| 里程碑 | 周期（参考） | 交付 |
| --- | --- | --- |
| M1 | ~2 周 | `ai_meta` + 阅读页手动标签建议 + 采纳/忽略 |

## 10. 验收标准

1. 解析成功 **不会** 自动产生任何 AI 请求或 `ai_meta` 变化。
2. 未点「AI 建议标签」时，该条 **无** 标签建议 UI（或仅显示入口）。
3. 点击后 pending → 成功展示 chips；未采纳前 `item_tags` 不变；采纳后合并正确。
4. 思维导图仅点击后生成；以脑图（非大纲列表）展示；缓存与 force 重生符合预期。
5. 无 Agent、无自动写库、无收藏夹 AI、**无设置内 AI 开关**。
6. 首次点 AI 入口弹出说明；点「继续」后才发请求；同账号仅弹一次。

## 11. 开放问题

1. AI 入口放 **更多 sheet** 还是正文下方固定条，或两者都有？
2. 采纳标签默认「合并」还是「替换为 AI 所选」？
3. 配额：免费用户每日手动触发次数上限？
4. 扩展（Chrome）是否二期支持手动 AI（还是仅 App）？
5. 收藏夹何时/如何弱化或下线？
