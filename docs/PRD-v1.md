## 1. 背景与问题

用户在微博、小红书、抖音、B 站、微信、网页等平台看到有价值内容时，习惯点平台内「收藏」。事后往往出现：

1. **不知道存在哪**：多平台收藏夹分散，找不到入口。
2. **搜不到**：平台内搜索弱，或内容被算法/时间线淹没。
3. **用不起来**：收藏等于「囤积」，无法在真正需要时快速召回原文。

同时，若要求用户「复制链接 → 打开 App → 粘贴 → 确认」走完 3～4 步，摩擦远高于平台原生一键收藏，产品难以养成习惯。

**一句话**：把多平台好内容收到一处，尽量接近「一键收藏」的成本，并能用关键词找回。

## 2. 产品目标

### 2.1 第一期目标（Must）

| 目标 | 说明 |
| --- | --- |
| 账号登录 | 手机号 + 短信验证码登录（登录即注册）；阿里云号码认证 |
| 合一收藏 | 用户通过链接将不同平台内容收入同一收藏库 |
| 内容解析 | 入库时解析链接，尽可能本地保存标题、正文、封面等（**非 AI**） |
| 阅读标注 | 在本地阅读正文过程中支持划线/高亮等标注（**非 AI**），并可从「标注」入口回看 |
| 可检索 | 支持关键词搜索，命中标题、正文、备注、标注原文、来源等字段 |
| 低摩擦入库 | 提供剪贴板检测、粘贴入库、快捷指令三条降门槛路径 |
| 手动分类 | 「我的收藏」提供系统筛选 + 收藏夹 + 标签 + 其他，便于整理 |

### 2.2 非目标（第一期不做）

- **智能列表 / 智能分类**（按规则自动生成列表、AI 自动归档等一律不做）
- AI 摘要 / 自动打标签 / 精炼 / 问答（第二期）——与「解析」「标注」无关
- 运营商**一键登录**（同属阿里云号码认证，可作后续增强；一期先短信验证码）
- 完整覆盖所有平台的深度反爬抓取（优先通用网页解析 + 常见平台尽力而为）
- 安卓侧对等「快捷指令」可后置；第一期优先 iOS 快捷指令，安卓用剪贴板 + 分享/粘贴兜底

## 3. 用户与场景

### 3.1 目标用户

- 重度信息消费用户：常在多社媒收藏干货、教程、灵感、商品种草等
- 希望「以后用得到」但讨厌收藏夹变成黑洞的人

### 3.2 核心场景

| 场景 | 用户行为 | 期望结果 |
| --- | --- | --- |
| 刷到好内容想存 | 复制链接 / 触发快捷指令 | 1～2 步内进入 Conflux 并开始保存 |
| 打开 App 时剪贴板已有链接 | 回到 App | **主动弹出添加链接弹框**并预填，确认即可保存 |
| 要用某类内容 | 在 App 内搜关键词，或进入某收藏夹/标签 | 快速找到条目并打开原文或看本地正文 |
| 整理收藏 | 移动到收藏夹、打标签、标星 | 内容按自己的主题归类，而非沉没在「所有」里 |
| 阅读并标注 | 打开已解析正文，划线高亮 | 重点留在文章里，可从「标注」筛选找回 |
| 回顾收藏 | 从「我的收藏」进入筛选/夹/标签再浏览 | 按时间看到标题、来源平台、封面 |

## 4. 方案总览

```
社媒/网页 ──复制链接──► 剪贴板 ──打开 App──► 自动弹出添加弹框 ──确认──► 解析入库
         └──快捷指令──► App Intent ─────────────────────► 解析入库
         └──打开 App 粘贴──────────────────────────────► 解析入库
                                                              │
                                                              ▼
                                    本地收藏库 + 阅读标注 + 关键词搜索 + 手动分类
                                                              │
                              ┌───────────────┬───────────────┴───────────────┐
                              ▼               ▼                               ▼
                         系统筛选         收藏夹（手动）                    标签（手动）
                   含解析/标注等…       未分类 + 用户自建               用户自建，多对多
```

**本期原则**：App 本地闭环可用；后端 Express + MySQL 仅作技术选型预留，第一期不依赖服务端。  
**分类原则**：只做用户可控的手动整理；**不做智能列表/智能分类**。

## 5. 功能需求

### 5.1 收藏入库

#### 5.1.1 粘贴入库

- App 内提供明显的「粘贴并保存 / 添加链接」入口（首页主操作之一）。
- **用弹框（Modal / Bottom Sheet）完成添加，不单独开页面**：弹出后可自动填入剪贴板 URL，也可手动粘贴/输入。
- 支持从剪贴板一键填入；也支持手动粘贴 / 输入 URL。
- 识别文本中的 URL（含短链）；若一段文本含多个链接，默认取第一个，或列出可选（实现阶段二选一，建议 MVP 取第一个并 Toast 提示）。
- 非法 URL / 无法解析时给出明确错误提示，不产生空条目（或产生「仅 URL、解析失败」条目，见 5.2）。
- **保存中 loading**：用户在弹框内点确认保存后，弹框内按钮进入 loading（或弹框内展示「保存中…」），快速取标题并完成入库前不可重复提交；成功后关闭弹框并进入详情或刷新列表；失败则结束 loading 并在弹框内/Toast 提示原因。

#### 5.1.2 剪贴板检测

- App **冷启动**或从后台 **回到前台**时检测剪贴板。
- 仅当剪贴板内容为（或包含）支持的 URL，且与「上次已提示/已保存/已忽略的链接」不同时触发。
- **主动弹出「添加链接」弹框**（与手动添加同一弹框），并自动填入检测到的链接；用户可直接点保存，或取消/忽略。
- **首页不展示**「检测到链接」横幅/提示条。
- 遵守系统粘贴权限：iOS 需处理用户拒绝粘贴的情况；检测应尽量使用「是否有 URL」类能力，减少无意义的粘贴权限弹窗打扰（实现按 Flutter 插件能力选型）。
- **不**在后台持续监听剪贴板；仅在前台生命周期节点检测。
- 用户取消弹框时，将该链接记入「已忽略」，短期或本次会话内不再因同一链接重复弹出。

#### 5.1.3 快捷指令（iOS 优先）

第一期至少提供可被「快捷指令」App 调用的能力：

| 指令 | 说明 |
| --- | --- |
| 从剪贴板保存 | 读取剪贴板中的链接并保存到 Conflux |
| 保存指定 URL | 接收传入的 URL 字符串并保存 |

体验要求：

- 用户可在系统分享菜单或自行配置的快捷指令中，用尽量少的步骤完成入库。
- 保存过程可在 App 内展示进度；若系统允许，快捷指令侧返回成功/失败结果文案。
- 安卓：第一期不强制对等「快捷指令」，可用系统分享到 App / 剪贴板方案作为替代说明写入后续迭代。

### 5.2 链接解析与本地保存（非 AI）

**解析**分两阶段（第一期都要做）：

| 阶段 | 时机 | 产出 |
| --- | --- | --- |
| **快速元信息** | 用户粘贴/确认保存链接后**立刻** | 优先拿到 **标题**（及尽量拿到封面、平台）；可先写库并展示 |
| **正文解析** | 入库后异步继续 | 可读正文 / summary；完成后 `status=success` |

标题不应等到用户打开详情页才去取：列表与详情头部在保存后应尽快出现真实标题。仅当快速取题失败时，才短暂用域名/URL 占位，并在正文解析阶段补齐标题。

对每个入库 URL，写入本地库的字段建议：

| 字段 | 说明 |
| --- | --- |
| id | 本地唯一 ID |
| url | 原始 URL |
| canonicalUrl | 规范化后的 URL（可选） |
| title | 标题（**保存时尽快写入**） |
| content | 正文或可读文本（异步解析） |
| summary | 摘要（可用 meta description 或正文前 N 字，**非 AI 生成**） |
| coverImageUrl | 封面图 URL（可选，能快取则与标题同阶段） |
| platform | 来源平台枚举/识别名（小红书、抖音、微博、B 站、网页等） |
| status | pending / success / failed（指**正文解析**；有标题也可仍为 pending） |
| errorMessage | 失败原因 |
| note | 条目级备注（可空；与阅读中的「标注」不同） |
| folderId | 所属收藏夹；默认未分类 |
| isStarred | 是否星标 |
| isUnread | 是否未读；新入库默认未读 |
| lastReadAt | 最近阅读时间 |
| createdAt / updatedAt | 时间 |

标签与条目为**多对多**。

行为约定：

- 保存后：条目立即出现在列表，**优先展示已取到的标题**；正文未完成时标记「解析中」。
- 正文解析成功：可本地阅读、可搜索正文。
- 正文解析失败：**仍保留 URL + 已有标题（若有）+ 失败状态**，可重试。
- 同一规范化 URL 重复保存：提示已存在，可跳转已有条目。

平台识别：按域名规则映射。无法识别则记为「网页」。

解析策略（第一期）：

- 快速阶段：HTTP(S) 拉取 HTML 头部 / Open Graph / `<title>` / meta（超时宜短）。
- 完整阶段：继续提取可读正文；对强反爬平台允许降级为「仅标题/链接 + 有限 meta」。

### 5.3 「我的收藏」分类（手动，无智能列表）

参考常见稍后读产品的「我的收藏」组织方式，第一期采用三段结构。**明确不做「智能列表」区块。**

#### 5.3.1 系统筛选（固定，不可删）

布局对齐常见稍后读产品：

- **未读**：可单独一行展示（无数据时显示「无」或 `0`）。
- 其余筛选项收在同一分组卡片内。

| 筛选 | 规则 | 第一期 |
| --- | --- | --- |
| 未读 | `isUnread == true` | 做 |
| 所有 | 全部条目 | 做 |
| 今天 | `createdAt` 为当天（本地时区） | 做 |
| 星标 | `isStarred == true` | 做 |
| 解析 | `status == success`（已成功解析出链接内容） | **做**（非 AI） |
| 标注 | 至少有一条阅读标注的条目 | **做**（非 AI） |
| 最近阅读 | `last_read_at IS NOT NULL`，按 `last_read_at` 倒序 | **做** |

说明：**智能列表整块不做**。「解析」「标注」均与 AI 无关，第一期必须交付。

> 命名：参考竞品或作「解读」处，本产品统一为 **解析**（解析链接内容）。若 UI 需与竞品对照，产品文案用「解析」。

#### 5.3.2 收藏夹（用户手动）

- 系统预置 **未分类**：新保存条目默认落入此处（或 `folderId` 为空时在 UI 归入未分类）。
- 用户可 **新建 / 重命名 / 删除** 收藏夹。
- 删除收藏夹时：夹内条目移回「未分类」，不级联删除条目（需二次确认文案说明）。
- 一条收藏同一时间只属于 **一个** 收藏夹。
- 在详情或批量操作中可「移动到收藏夹」。
- 第一期收藏夹为**单层**，不做嵌套子夹（降低复杂度；日后可扩展）。

#### 5.3.3 标签（用户手动）

- 独立分区，标题「标签」，可折叠；支持「+」新建；可提供简单排序入口（如按名称 / 按数量，MVP 可只按名称）。
- 用户可 **新建 / 重命名 / 删除** 标签。
- 一条收藏可打 **多个** 标签；在详情中增删标签。
- 删除标签：仅解除关联，不删除条目。
- **不做**根据内容自动生成标签。

#### 5.3.4 其他

「我的收藏」在收藏夹、标签之外增加 **其他** 分区，收纳不属于前两类的系统入口，避免和收藏夹/标签混在一起。

第一期建议包含：

| 入口 | 说明 |
| --- | --- |
| 回收站 | 删除的条目先进入回收站，可恢复或彻底删除；保留期限实现自定（如 30 天，MVP 可永久直到用户清空） |

一期可不做、二期再加的「其他」项（仅占位说明，不开发）：归档、损坏/抓取失败合集等。

#### 5.3.5 「我的收藏」页交互

- 分区顺序：**系统筛选 → 收藏夹 → 标签 → 其他**（无智能列表）。
- 收藏夹、标签、其他（若含可建项）分区可折叠；夹与标签支持「+」新建。
- 点击任一筛选 / 夹 / 标签 / 其他入口 → 进入对应条目列表（复用列表组件）。
- 各入口右侧展示条目数量（未读无数据时可显示「无」）。

### 5.4 本地阅读与标注（非 AI，第一期必做）

**标注** = 用户在阅读已解析正文时，对片段做的划线/高亮（可附短备注），便于日后回看重点。与条目级 `note`、与 AI 无关。

#### 5.4.1 阅读页

- 解析成功的条目可进入 **本地阅读页**，展示已保存的 title / content（清晰可读排版）。
- 解析失败时：阅读页不可用；从详情重试解析。
- 进入阅读可将未读标为已读，并更新 `last_read_at`。
- 标注（划线高亮）在阅读页完成。

**底部操作栏（固定）**

- 固定在阅读页最底部，不随正文滚动消失。
- 底栏从左到右：**标注 / 星标 / 标签 / 更多**（无「目录」）。
- **最右侧为「更多」**；点击后弹出操作面板（Bottom Sheet），承载其余操作。

**「更多」面板（第一期建议项）**

| 操作 | 说明 |
| --- | --- |
| 移动收藏夹 | 调整所属收藏夹 |
| 备注 | 编辑条目备注 |
| 删除 | 移入最近删除 |

> 打开原文：第一期不做。更多面板为 **Grid 宫格布局**（图标 + 文案）。星标、标签在底栏直接操作，不放进更多面板。

#### 5.4.2 标注操作

- 选中正文片段 → 添加标注（至少支持高亮；可选颜色 MVP 可单色）。
- 可为该标注附加一句短注（可选）。
- 支持删除单条标注。
- 阅读页内可看到已有高亮；点击高亮可查看/编辑短注或删除。

#### 5.4.3 标注数据（建议）

| 字段 | 说明 |
| --- | --- |
| id | 标注 ID |
| itemId | 所属收藏 |
| selectedText | 选中的原文片段 |
| startOffset / endOffset | 在 content 中的位置（实现可选等价方案） |
| color | 高亮色（可选） |
| annotationNote | 标注短注（可空） |
| createdAt | 时间 |

#### 5.4.4 与「标注」筛选的关系

- 「我的收藏 → 标注」列出所有 **至少有一条阅读标注** 的条目。
- 条目详情或阅读页可展示本篇标注列表，便于跳转定位（MVP 可先列表展示选中文本，精确定位为增强）。

### 5.5 条目列表与详情

- **列表**：按创建时间倒序；展示封面（有则）、标题、平台、时间、解析状态；可显示星标、是否有标注、所属夹/标签摘要。
- **搜索**：关键词匹配 title / content / summary / url / note / platform / 标签名 / 标注选中文本与短注；MVP 可先做全局搜索。
- **详情**：元信息 + 正文预览 + **进入阅读** / 重试解析；**不含**打开原文、星标、标签（后两者在阅读页）。
- **删除**：需确认（进入回收站，见「其他」）。

### 5.6 空状态与引导

**首次引导（登录之后）**

- 出现时机：**登录成功之后**（含首次自动注册）；未登录不展示。
- 触发条件：本机或该账号尚未完成过首次引导（本地标记即可，如 `onboarding_seen`）。
- 内容：说明 **三种入库方式（任选其一）**——剪贴板检测 / 粘贴添加 / 快捷指令（可选）；不是强制按序完成的步骤。
- 用户点「开始使用」后进入主壳；之后默认不再弹出。
- 设置中可再次打开「iOS 快捷指令说明」「如何添加链接」等帮助页。

- 无搜索结果 / 某夹为空：明确「无匹配」或「暂无收藏」，不要空白无反馈。

## 6. 信息架构（App）

一级页面共三个：

```
登录页（未登录唯一入口）
  └─ 登录成功
        ├─ 未看过引导 → 首次引导（三种入库方式）→ 主壳
        └─ 已看过引导 → 主壳（底部双 Tab）
              ├─ 首页：未读 / 标注 / 最近阅读 三板块（各取前几条 + 查看更多）
              └─ 我的收藏：分类导航（系统 / 收藏夹 / 标签 / 其他）
```

### 6.1 登录页

- 手机号 + 短信验证码
- 登录成功后：若未完成首次引导则先进入引导页，否则进入主壳；未登录不可进入首页 / 我的收藏

### 6.2 首页（三板块，不再铺全部 item）

顶部：搜索、添加（点出添加弹框）。  
剪贴板检测到新链接时直接弹出添加弹框，**首页不展示「检测到链接」横幅/提示条**。

| 板块 | 内容规则 | 「查看更多」 |
| --- | --- | --- |
| 未读 | `is_unread=1`，按 `created_at` 倒序，**最多 3 条** | 进入「我的收藏 → 系统筛选 → 未读」列表 |
| 标注 | 至少有一条阅读标注的条目，按最近标注/更新时间倒序，**最多 3 条** | 进入「我的收藏 → 系统筛选 → 标注」列表 |
| 最近阅读 | `last_read_at IS NOT NULL`，按 `last_read_at` 倒序，**最多 3 条**（可配置） | 进入「我的收藏 → 系统筛选 → 最近阅读」列表（**不单独开二级页**） |

空板块：该块显示空状态文案，不占假数据。  
点击条目 → 详情 / 阅读页；进入阅读时更新 `last_read_at`，并将 `is_unread` 置为已读（与既有约定一致）。

### 6.3 我的收藏（分类）

```
我的收藏
 ├─ 系统筛选：未读 / 所有 / 今天 / 星标 / 解析 / 标注 / 最近阅读
 ├─ 收藏夹：未分类 + 用户自建 → 进入该夹下的条目列表
 ├─ 标签：无标签 + 用户自建 → 进入该标签下的条目列表
 └─ 其他：回收站（最近删除）→ 对应列表
```

从第二层入口进入的条目列表，与首页板块「查看更多」共用列表组件，仅过滤条件不同。

### 6.4 内容详情页

进入任一条目后的详情页，结构分两段：

1. **头部（始终展示）**
   - **标题**：保存链接时已尽量取到，进入详情即显示真实标题（不是等正文解析完才出现）
   - 时间（创建时间；有最近阅读可另显）
   - **正文解析状态**：正在解析 / 解析完成 / 解析失败
   - 来源平台、原始链接（仅展示，第一期不提供打开原文）
2. **内容区（随正文解析状态变化）**
   - `pending`：骨架/进度，表示正文仍在解析；**头部标题已可用**
   - `success`：展示封面（若有）+ 本地解析正文预览；**「进入阅读」固定在页面底部**（不随正文滚动消失）；阅读页内再做星标、标签、标注等
   - `failed`：失败说明 + 重试解析
   - **不做「打开原文」**（第一期）

设置 / 快捷指令说明 / 关于：可放在首页或我的收藏的次级入口（非一级 Tab）。

### 6.5 阅读页

```
阅读页
 ├─ 顶栏：返回
 ├─ 正文区：标题 + 可读正文（含已有高亮）
 └─ 底部操作栏（固定）：标注 / 星标 / 标签 / 更多
      └─ 更多 → Grid 面板（移动收藏夹 / 备注 / 删除 …）
```

## 7. 关键用户流程

### 7.1 剪贴板保存（目标：社媒 1 步 + App 内确认）

1. 用户在社媒点击「复制链接」
2. 打开 / 切回 Conflux
3. **自动弹出「添加链接」弹框**，已填入该链接
4. 点保存 → 弹框内 loading → 入库；或点取消（短期不再对同一链接弹框）

### 7.2 粘贴入库

1. 用户在首页点「添加 / 粘贴并保存」→ **弹出添加链接弹框**（非新页面）
2. 自动填入剪贴板 URL（或手动粘贴）
3. 确认保存 → 弹框内 loading → 快速取标题并入库 → 关闭弹框；正文可后台继续解析

### 7.3 快捷指令

1. 用户预先安装「从剪贴板保存到 Conflux」快捷指令（或系统分享到该动作）
2. 在社媒复制链接后执行快捷指令
3. App 接收并保存，返回成功反馈

### 7.4 分类整理

1. 用户在「我的收藏」新建收藏夹或标签
2. 在**阅读页**打标签 / 星标；收藏夹移动可在详情或阅读页（后续定）
3. 之后从对应夹或标签进入，只看该主题内容

### 7.5 阅读与标注

1. 详情页点「进入阅读」→ 本地阅读页
2. 底部操作栏：标注 / 星标 / 标签；**点最右侧「更多」弹出 Grid 面板**（移动收藏夹、备注、删除等）
3. 选中正文可添加高亮标注（细节可继续补充）
4. 在「我的收藏 → 标注」中找回做过标注的文章

### 7.6 手机号登录与首次引导

1. 打开 App → 登录页输入手机号 → 获取验证码
2. 后端调用阿里云号码认证 `SendSmsVerifyCode` 下发短信
3. 用户输入验证码 → 后端 `CheckSmsVerifyCode` 校验
4. 校验通过：若手机号无账号则自动注册，写入登录态
5. **若未完成首次引导** → 展示首次引导（三种入库方式，任选说明）→ 点「开始使用」进入主壳  
   **若已完成** → 直接进入主壳

## 9. 成功标准（第一期验收）

1. 可用手机号验证码完成登录/自动注册，并获取有效登录态。
2. 用户可通过 **粘贴入库** 保存链接（归属当前用户），并在列表看到条目。
3. App 从后台回前台时，若剪贴板为新链接，**主动弹出添加链接弹框**并预填；取消后短期不再对同一链接打扰。
4. iOS 上可通过快捷指令完成「从剪贴板保存」或「保存指定 URL」。
5. **解析**：成功条目可本地阅读正文/摘要，且可被关键词搜索命中；失败可重试。
6. **标注**：阅读中可对选中文本高亮标注；「标注」筛选能列出相关条目。
7. 重复 URL 有明确提示；删除进回收站。
8. 「我的收藏」含：系统筛选（含解析、标注）+ 收藏夹 + 标签 + 其他；**无智能列表**。
9. 用户数据按账号隔离，无法读写他人数据。
